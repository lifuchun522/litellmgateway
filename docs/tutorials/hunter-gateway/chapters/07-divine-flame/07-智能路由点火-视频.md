同一逻辑模型必须能打到多个后端，选路过程还得能翻出来查。谁负责，什么时候能看？
客户只为一句承诺买单：换后端不改代码。Explain 是差异化，不是内部调试日志。
客户最气的是同一个模型这次慢十倍。没有 explain，一线只能道歉，问题还会重复。
LiteLLM 和 OpenRouter 都已提供权重与最低延迟路由，官方文档可核。这是趋势不是个例。
一期只做优先级、权重、随机、最低延迟四种策略，加候选过滤和模拟页，不做自动调权。
方案 A 是策略接口加过滤器链，方案 B 是单函数 if-else。我选 A，代价是多一层抽象。
过滤后候选为空就返回 503 并写 explain；权重全零、样本不足都必须有明确兜底。
基线是单后端直连的 P95。成功线定成路由错误率低于百分之零点五，决策可复现。
开发者会搜可解释路由、模型路由 explain。文档页要能被收录，并且一搜就命中。
这章不投付费。开发者工具靠 GitHub 和云社区自然量，本期 CAC 为零是唯一判断。
多实例常驻每月多烧一笔钱。ROI 门槛先定死：P95 降三成才继续加实例。
Explain 不能落 prompt 和用户身份，只留候选与过滤原因。谁越权谁负责，写清楚。
分工：Bob 定接口契约，Alex 写实现，Emma 管验收。分支用 chapter/07-routing。
砍掉动态自适应权重，先把 explain 做扎实。不做会怎样？答：没人敢开第二个后端。
销售口径改成可解释可回退，绝不承诺自动最优。客户听得懂，也才敢开灰度。
工单系统要能按 request id 回放 explain，一线三分钟内给答复，这就算闭环。
有团队用最低延迟路由后长尾抖动更严重。建议最少二十次采样才允许参与排序。
范围冻结：四策略、候选过滤、explain、模拟页。自动调权和跨区调度直接砍掉。
牺牲绝对最优，换可解释可回退。策略可插拔，将来加第五种不用动路由核心。
RoutePolicy 表存权重与优先级，Target 挂实例。模拟接口只读，不写任何生产状态。
样本少于二十次就退回权重路由；错误率超百分之三自动降级，并且立刻告警。
文档页加结构化数据，关键词覆盖可解释路由与 explain，直接指向在线模拟页。
本期不投广告，预算留给第 08 章可观测性。真要投，也只测路由模拟页的转化。
预算上限每月三个新增实例，超了先砍随机策略灰度，保住优先级和权重路由。
Explain 脱敏加保留七天，责任边界写进 SLA 附件。这样才敢让它上生产环境。
交接清单：Bob 契约 T+2，Alex 实现 T+5，Emma 验收 T+6，合并后必须跑模拟。
就一个方案：四策略加候选过滤加 explain。验收：同一逻辑模型按策略分到多实例。

## 摘要

同一逻辑模型如何按优先级、权重、随机、最低延迟分到多个后端，并留下可查的 explain。
