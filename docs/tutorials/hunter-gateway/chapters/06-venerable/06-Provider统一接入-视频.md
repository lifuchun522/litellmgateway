第06章只做 ProviderAdapter SPI 和 OpenAI 兼容适配器，验收一条：跑通两个上游。
客户不问 SPI，只问能不能今天接上 DeepSeek 和本地 Ollama，五分钟换模型，别让我改代码。
上周三个工单全是换供应商重配，客户在配置页迷路，报错只显示 500，没人知道是 key 还是网络。
五家文档我都比过：OpenAI、DeepSeek、Qwen 是 /v1，vLLM 和 Ollama 鉴权不同。
一期只交付 CRUD、测试连接、同步模型、启停四件事，五个上游都是配置，不做五份适配器代码。
两个候选：一个 SPI 加五个独立实现；或者一个 OpenAI 兼容实现加注册表，差异收进配置和能力位。
六方法我都认，但 stream 要处理 SSE 断流，mapError 要归一错误体，两天写不完，先跑通。
现在接一个新上游平均两小时，目标压到十分钟以内；成功率低于九成五就算没做成。
搜 LiteLLM 网关怎么接 Ollama 的人很多，文档给一张兼容矩阵和可复制配置，才是真的自然流量。
这种开发者工具我不会先投钱，CAC 撑不住；先靠文档和 GitHub 搜索拿量，除非要验证企业关键词。
五家上游都留 key 就是五个风险口子，探针调用还烧钱，先只给两家预算，超支就停。
apiKeyCipher 用 AES-GCM，密钥走环境变量，日志和接口都不许返回明文，这是红线。
先把范围锁住：Bob 定接口契约，Alex 写实现，我和 Emma 定验收，第三天必须看到两个上游通。
好，我不坚持五家一起上，但配置页必须做到换 key 换 baseUrl 不改一行代码，这是卖点。
我选方案二：牺牲每家特殊能力，换来一个实现；差异用 headers 和 proxy 兜住，要扩再加适配器。
断开流我用 SSE 心跳加超时兜底，错误统一进 mapError 映射表；重复调用靠 requestId 幂等。
预算就两家上游加一台测试机，一个月不超过两百块，探针默认关闭，人工触发才算钱。
AES-GCM 密钥不落库，解密只在调用瞬间，页面只回掩码；这样写进设计文档，我签字。
冻结：CRUD、测试、同步、启停、掩码展示；不做多租户配额，也不做自定义插件加载。
成功线：两个上游 invoke 和 stream 都通；停止线：连续两天超时率过百分之五。
我要的是报错能看懂：key 错了、模型不存在、超时三种提示分开，客户自己就能改。
提醒一句，Qwen 兼容端点的流式返回字段和 OpenAI 有细微差别，映射表必须留扩展位。
文档加兼容矩阵和 curl 示例，落地页指向快速开始；两周内看自然搜索点击和 Star 增长。
这轮不投付费，只埋转化事件；如果两周自然量低于预期，再拿一千块测一次关键词。
Owner 是 Bob、Alex、Emma：Bob 定接口，Alex 写实现，第五天验收两个上游通。
就一个适配器两个上游，SPI 六方法先定死，其他配置兜底；第五天不通过，砍到只留 invoke。
