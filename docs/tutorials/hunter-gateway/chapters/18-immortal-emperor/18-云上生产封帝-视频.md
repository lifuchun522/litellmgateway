第18章只做一件事：把Java LLM Gateway塞进K8s生产环境。全链闭环，不做完不算完。
客户只认一件事：OpenAI SDK进来到Console看到成本和状态，中间不能断。
主Provider挂了怎么办？Pod重启SSE断不断？客户不会看架构图，他只看工单有没有人接。
多Pod共享RateLimit本地内存一定串。Redis集中计数是业内标准，三个开源网关都这么做。
一期砍到四条：容器化、K8s编排、Redis共享计数、全链验收。多租户和计费分级不做。
两个候选：每Pod本地计数加定时同步，或直接迁Redis原子计数。前者省依赖会超发，后者可审计。
SSE滚动升级会断流，readiness没过接流量会打爆新Pod。Redis热点Key要提前分片。
没有基线就没有验收。先跑同步和SSE压测，拿到P95、429率和Fallback率再谈成功线。
开发者搜Java LLM Gateway自部署和K8s部署。Console放版本、实例、依赖健康。
这期不投广告。开源项目靠GitHub和社区自然扩散，CAC为零。付费验证等托管服务再说。
K8s集群和Redis都是固定成本。我的线是每月增量不超两千，超了就得证明能带来收入或留存。
Provider Key不进镜像和ConfigMap。K8s Secret是底线，有条件上外部Secret Manager。
分支chapter/18-k8s-production，Docker和K8s两段并行，合并全链验收。
听完Redis和Secret讨论，范围再收紧：不做多租户，不做计费分级，只保单租户全链闭环。
最终选Redis原子计数。牺牲一次网络延迟，换来多Pod计数一致和可审计。本地计数降级缓存。
SSE滚动升级用preStop加宽限期，新Pod readiness跑通再切流量。
成功线：同步P95小于800毫秒，SSE首字节小于500毫秒，429率低于1%。错误率超5%回滚。
Console首页加一行：版本、实例状态、配置版本、依赖健康。开发者截图就能传播。
这期预算还是零。后面做托管版先测CAC，单注册超五十块就停，ROAS不到三不加预算。
按Bob和Alex的方案，Redis加节点和带宽每月约一千二，在两千线内。超出必须新审批。
Secret挂载用只读，Key轮换要有Owner和记录。Provider故障降级写进运维手册。
Owner：Alex管Docker和JVM，Bob管K8s和Redis，David管压测，Mike管合并提交。
我不承诺零故障，只承诺故障可见可恢复。Console上实例状态和Fallback次数实时更新。
我加一条验收：杀Pod后SSE客户端三十秒内自动重连；主Provider切Fallback十秒出新状态。
我补一个反证：Redis单点会变新瓶颈。必须配哨兵或集群，否则共享计数反而降低可用性。
拍板：走Redis原子计数，K8s多阶段非root镜像，全链验收。做完这一条链，再谈下一章。
