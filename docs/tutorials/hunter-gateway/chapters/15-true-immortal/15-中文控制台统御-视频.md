# 荒天帝炼大模型网关-第15境-真仙境-八九天功-中文控制台统御

第15章只做一件事：复用 Demo 现有 UI，把管理台闭环跑通，不重写路由和基础组件。谁反对？
客户要自己配 Provider、Model、路由和 Key，再进 Playground 验证。没闭环就砍。
客户最烦配置完不知道哪一步错。日志详情必须给 RuntimeContext、RouteAttempts 和错误。
我查了同类网关管理台，Provider、路由、Key、Playground 是刚需；Dashboard 只留六指标。
一期冻结：11 个菜单、最小 Admin 登录/RBAC、纯页面闭环。Prompt 默认不落库。
前端有两个候选：一，复用 Demo UI 框架增量加页面；二，重写新管理台。重写拖三周，我推复用。
复用有坑：菜单权限、路由守卫、Playground 流式、日志字段映射。接口契约先定。
Dashboard 先定基线：成功率按 2xx 除以总请求，P95 按网关入站到响应完成；Cost 缺失就标未知。
开发者会搜 LLM Gateway 管理台、Playground 调试、虚拟 Key。页面标题要能收录，但一期先做可用。
这次不投付费。管理台是内部转化工具，CAC 无法归因；预算留给 Playground 性能埋点，看激活率。
复用 Demo UI 省掉重写成本。预算线：两周人力，不超过 10 人日；超过就砍 Dashboard 图表和系统页。
日志默认不落 Prompt，这是红线。RuntimeContext 只存脱敏字段；RBAC 最小权限，操作留审计。
第一轮结论：复用 UI、11 菜单、六指标、Playground、日志详情、最小 RBAC。下一棒锁接口、拆页面。
听完技术约束，我改承诺：不承诺自定义仪表盘，只承诺管理员十分钟完成 Provider 到 Key 再跑 Playground。
一线标准：错误信息必须带 route attempt 和上游状态码；否则工单重复。日志详情先上这四项。
外部证据一致：同类产品都把 Playground 放核心导航。但 Cost 口径普遍不统一，建议先标估算。
范围再冻结：不做多租户、不做计费、不做 Prompt 存储；系统页只保留版本和健康。验收只认闭环。
最终取舍：复用 Demo UI，牺牲视觉自由度，换两周交付和低回归；接口用现有网关契约。
实现路径：新增 admin 路由与菜单，Playground 走 stream，日志详情映射 RuntimeContext 和 RouteAttempts。
成功线：十分钟闭环，成功率≥99%，P95≤800ms；失败率>20% 就回退旧配置页。
自然增长验证：发中文快速上手，埋 UTM 看搜索进入的注册和 Playground 首次运行；两周无收录就改标题。
如果做付费，CAC 上限 80 元，ROAS 要大于 1.5；但一期先不投，转化事件埋好，激活率过 15% 再测。
预算锁死 10 人日，ROI 门槛：闭环后每周省 5 小时人工配置，六周回本；超支就砍 Usage 详情和系统页。
合规路径可行：登录、RBAC、审计日志、Prompt 不落库写进文档；红线是明文密钥不展示，谁绕过谁负责。
Owner：Alex 前端，Bob 接口，Emma 验收。D+10 提 chapter/15-admin-console，提交 feat(ch15)。
拍板：第15章按复用方案做，不做重写、不做计费、不做 Prompt 落库。D+10 闭环验收，失败回退旧管理页。
