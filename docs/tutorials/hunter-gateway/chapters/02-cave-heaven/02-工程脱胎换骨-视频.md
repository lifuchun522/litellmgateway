第2境柳神法：只换骨，不重生。保留 Demo 骨架，改包名和品牌名，禁止顺手重构。谁越界谁负责回退。
客户不会看包名，但会看到产品还叫 demo、叫 open-api。对外品牌必须一次换干净，否则第一眼就不专业。
一线最怕升级后启动不了。老前缀写死在客户 yml 和脚本里，改名当天就有工单，必须留兼容窗口。
改名翻车点集中在三处：spring.factories、MyBatis namespace、yml 前缀。IDE 重命名只覆盖代码，字符串得单独扫。
一期范围三件事：标识改名、配置前缀兼容、回归通过。拆模块、改架构、加功能，全部写进 Not Do 清单。
两个候选：A 全量改名一次到位，B 代码改名、配置前缀双读过渡。A 干净但会中断，B 多一层兼容但不停机。
既然要动包名，顺手把 open-api 拆成 core 和 admin 更省事，一次做完。迁移脚本我写，编译我保证过。
验收不靠感觉。基线是第1境全部接口回归通过：接口清单、返回码、响应体逐项比对，差异数必须是零，不是差不多。
改名顺手修可发现性：README 首屏写清 Java 轻量级 LLM Gateway，仓库名与包名一致，开发者和搜索才认得。
这次不投钱。改名的曝光价值到不了付费门槛，CAC 无从计算，也没有可归因的转换事件。预算留给第3境发版。
预算线：两人五天，零新增云成本。超一天要么砍范围，要么停手回退，不允许把重构算进这笔预算。
改名不是法务问题，但商标和依赖许可证是。新名不得撞已有商标，Apache 类许可证和 NOTICE 必须随包保留。
下一棒：Alex 出迁移脚本，Emma 冻范围，David 定回归清单。我卡三个门——迁移完成、编译通过、回归零差异。
双读可以，但兼容期只给一个月：新前缀为主，旧前缀打废弃警告。对外品牌名一次换干净，不留旧名。
一个月够，但要有迁移提示：旧前缀一启动就在日志和健康检查里提示新写法，工单量才压得住。我按这个验。
补个反证：跨包名迁移后 SPI 与自动配置最容易漏。回归加一条——全仓库扫描旧包名，命中数必须为零。
范围重冻：做标识改名、双读一个月、回归零差异；不拆模块、不加功能、不改接口路径，结构留到第3境。
最终选 B：牺牲彻底干净，换来客户不停机。代价是留一层兼容分支和一个月后要删的旧前缀，删除项进技术债清单。
路径锁死：先扫清单，再批量迁移，然后编译、测试、接口回归。我第一轮想拆的模块，这次一个都不动。
成功线：回归全过，旧包名命中为零。停止线：接口返回体出现任何字段差异，立即回退基线分支，不许现场改代码。
我的验证指标：仓库名与包名一致、README 首屏关键词命中、引用旧名的外链两周内清空。这是发现路径，不是写文章。
仍然零投放。转化事件还没埋，这点流量算不出 CAC。第3境接口稳定后，我再拿发布页做一次小额归因测试。
预算维持两人五天，上限不变。兼容分支按每月半天维护计，一个月后必须清掉，否则这层代码会一直吃利息。
红线三条：不撞已有商标、NOTICE 与 LICENSE 原样保留、改名记录写进仓库说明。这三条过了，重命名就能签。
落执行：Alex 出迁移脚本 T+2，David 出回归清单 T+1，Emma 锁范围今天。验收统一一条——第1境能力零丢失。
拍板：第2境只换骨。根包 cloud.joysky.llmgateway，分支 chapter/02-rename-baseline，回归零差异才算交付。
