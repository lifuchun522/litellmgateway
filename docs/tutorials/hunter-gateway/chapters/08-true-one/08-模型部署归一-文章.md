# 彻底分开 LogicalModel、Deployment、Provider：Java 网关的三层归一

> 客户端只认别名，供给随你怎么换

```text
[读者] 正在给团队做 LLM 网关的后端工程师
[痛点] 换一个上游模型，客户端要跟着改模型名
[现在读] 你已经跑通了 Demo，但那张 model 表快撑不住了
[读完] 一套可落地的三层模型与路由骨架
```

```text
[旧方案] 一张 model 表：别名、上游名、BaseURL、Key、价格全塞一起
    |
    v
[新需求] 同一个别名挂多个上游，换 Provider 不能影响客户端
    |
    v
[冲突] 三种变化频率完全不同的东西绑在同一行配置里
    |
    v
[后果] 改价动全表，换 Key 要发版，灰度无从下手
```

我是老李，在深圳做了十来年后端，最近拿 litellmgateway 的 open-api.zip Demo 做逆向（https://github.com/lifuchun522/litellmgateway ），准备在它上面长出一个 Java 轻量级 LLM Gateway。我的做法是：先把 Demo 读透，再改包名和项目名，然后在现有代码上增量加能力，而不是另起一套脚手架。

前面几境里，我已经把 OpenAI 兼容协议、Gateway Pipeline、Provider 适配打通了。到这一境，任务是：把客户端看到的模型名和上游真实模型彻底解耦——客户端说 `coding-fast`，网关自己决定这次到底打给谁。

一开始我觉得这事不难，加一张别名映射表就完了。真做下去才发现，量级完全不是加一张表。

客户端模型名到底该由谁定义——让客户端填一个上游模型名，还是由网关给出一个稳定契约？

换上游 Provider 的时候，为什么不该动客户端的任何一行配置——这是洁癖，还是硬需求？

价格改了以后，历史账单怎么办——把新价格覆盖到旧记录上，月底对账会发生什么？

# 01、故事

第一阶段的网关，本质上是一张表。字段大概是 `id / alias / provider / base_url / api_key / upstream_model / input_price / output_price / context_window`，一行就是一个能用的模型。客户端请求 `POST /v1/chat/completions`，`model` 字段填表里的 alias，网关查一行，拿 base_url 和 key 转发出去。跑 Demo、接一个用 OpenAI SDK 写的客户端、在 Playground 里点两下，全都通。

变化是三个方向同时来的。

第一，产品要三个逻辑别名：`coding-fast`、`general-chat`、`reasoning`。客户端只认这三个名字，至于背后是自建推理服务、某家云厂商的托管模型，还是第三方中转 API，客户端不关心，也不该关心。

第二，运维要动 Provider。Key 要轮换，Base URL 会因为专线、代理层或者多区域部署而调整。这些是运维动作，不该触发客户端发版。

第三，价格会调。调完之后，上个月已经出账的费用不能跟着变。

矛盾立刻出现：`coding-fast` 要同时挂两个上游做灰度，但 `model` 表里 alias 唯一，一行只能有一个 base_url、一个 api_key、一个 upstream_model。想挂第二个，只能加一行 `coding-fast-v2`，然后把客户端改成 `coding-fast-v2`——解耦了个寂寞。

> 一行配置里
> 挤着三种变化
> 别名一出口
> 上游已千里

# 02、问题

旧方案失效的地方很具体：`model` 表把三类信息焊死在同一行——客户端的契约（别名、类型、能力）、一次具体供给（上游模型名、上下文长度、权重）、一条网络通道（Base URL、认证、代理）。这三类东西的变化频率差了一个数量级，却被写进了同一行。

业务影响有三层。第一层是发布节奏被拖慢：换一个上游 Key，要改配置、要走一次发布流程，而这次发布对客户端毫无收益。第二层是灰度失去抓手：同一个 `coding-fast` 没法按比例分流到两个上游，做不了小流量验证。第三层是账目不可追溯：价格被覆盖之后，没有任何地方能还原出上个月那次调用到底按什么价格计费。

技术表现集中在两处：一是别名字典和上游配置耦合，任何一次上游变更都会改变客户端可见的配置面；二是计费链路里没有价格快照，报表是 join 当前配置实时算出来的，本质上是拿现在的价格解释过去的事实。

可验证的完成标准，我定成四条：

1. 客户端只发 `coding-fast`，网关换成另一个 Provider 之后，客户端不改一行配置、不发版，请求依然成功；
2. 一个 LogicalModel 可以绑定多个 Deployment 并按权重分流，一个 Provider 可以承载多个 Deployment；
3. 改一次价格之后，历史用量重新出账，数字不变；
4. 管理页面能画出别名到部署再到通道的关系图，不依赖外部文档。

> 改价动全表
> 换Key要发版
> 别名成枷锁
> 客户端陪跑

# 03、原理

这一境真正要讲的原理只有一句：变化频率不同的东西，不要放进同一个实体。

把网关要表达的语义摊开，其实只有三件事：客户端要什么、这次由谁来满足、从哪条路走。

- LogicalModel 是契约：alias、modelType、capabilities。它面向客户端，稳定性要求最高。
- Deployment 是一次供给：provider 加 upstreamModel、price、context、health、weight 与 priority。它面向运营，随时可变。
- Provider 是通道：Base URL、认证、网络配置。它面向基础设施，变更频率最低。

三者之间是两个一对多：一个 LogicalModel 绑多个 Deployment，一个 Provider 承载多个 Deployment。

反直觉判断一：拆开之后实体变多了、表变多了、查询也变多了，短期看复杂度是上升的；但变更的爆炸半径从全表加客户端发版，缩到一行部署记录，长期看复杂度是下降的。多出来的那点结构复杂度，买到的是变更自由度。

反直觉判断二：价格不该挂在 LogicalModel 上。它听起来像模型属性，但同一个 `coding-fast` 挂在两个上游，输入输出价格本来就可以不一样；把价格放在契约层，等于强行要求所有供给同价。价格属于 Deployment，而且必须版本化——Deployment 只引用当前价格版本，历史用量记录引用当时的价格版本。

这一境的功法讲的是归一：归一不是把东西合并成一块，而是让外面看到的是一个稳定本体，里面怎么换都行。网关的对外本体，就是 LogicalModel。

> 变化各有频
> 同表必相扰
> 契约须稳定
> 供给可常换

# 04、架构

```text
[输入] POST /v1/chat/completions { model: coding-fast }
    |
    v
[模块] LogicalModelResolver → DeploymentSelector → ProviderClient
    |
    v
[数据/状态] LogicalModel / Deployment / Provider / PriceVersion / healthState
    |
    v
[处理] 解析别名 → 按 priority/weight/health 选部署 → 装载通道与认证 → 转发上游
    |
    v
[输出] 上游响应 + UsageRecord(deploymentId, priceVersionId, tokens)
```

边界：网关只决定这次选谁、从哪条路走，不替上游做能力编排，也不做模型质量评估。capabilities 只用于准入校验——客户端要 `vision`，而 Deployment 的能力集里没有，就在网关侧拒绝，不浪费一次上游调用。

收益：契约与供给分离，换通道变成运维动作；灰度、计费、限流都有了挂载点。

代价：一次请求从查一行变成解析、选择、装载三步，虽然都可以缓存，但缓存失效策略本身又是新的复杂度；另外 deployment 的权重、优先级、健康状态需要有人维护，配置面比原来大。

适用条件：多上游、多租户、需要计费和灰度。如果你的网关只连一个上游、只有一个模型，三层分离是过度设计——但要清楚这是暂时不需要，不是不必要。

> 别名定契约
> 部署管供给
> 通道只承载
> 三层各安位

路由决策是一个不可变记录，它把选择的全部依据一次带出去，避免下游再回表。

```java
package com.example.gateway.routing;

import com.example.gateway.domain.Deployment;
import com.example.gateway.domain.LogicalModel;
import com.example.gateway.domain.PriceVersion;
import com.example.gateway.domain.Provider;

public record RouteDecision(LogicalModel logicalModel,
                            Deployment deployment,
                            Provider provider,
                            PriceVersion priceVersion) {

    public String upstreamUrl() {
        String base = provider.getBaseUrl();
        String path = provider.getChatPath() == null ? "/v1/chat/completions" : provider.getChatPath();
        if (base.endsWith("/")) {
            base = base.substring(0, base.length() - 1);
        }
        return base + path;
    }
}
```

解析器是这一境的主角：先解析契约，再按优先级分层、按权重随机、按健康状态过滤，最后装载通道与价格版本。

```java
package com.example.gateway.routing;

import com.example.gateway.domain.Deployment;
import com.example.gateway.domain.LogicalModel;
import com.example.gateway.domain.PriceVersion;
import com.example.gateway.domain.Provider;
import com.example.gateway.repository.DeploymentRepository;
import com.example.gateway.repository.LogicalModelRepository;
import com.example.gateway.repository.PriceVersionRepository;
import com.example.gateway.repository.ProviderRepository;
import org.springframework.stereotype.Service;

import java.util.List;
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.ThreadLocalRandom;

@Service
public class ModelRouter {

    private final LogicalModelRepository logicalModelRepository;
    private final DeploymentRepository deploymentRepository;
    private final ProviderRepository providerRepository;
    private final PriceVersionRepository priceVersionRepository;
    private final ConcurrentHashMap<Long, Provider> providerCache = new ConcurrentHashMap<>();

    public ModelRouter(LogicalModelRepository logicalModelRepository,
                       DeploymentRepository deploymentRepository,
                       ProviderRepository providerRepository,
                       PriceVersionRepository priceVersionRepository) {
        this.logicalModelRepository = logicalModelRepository;
        this.deploymentRepository = deploymentRepository;
        this.providerRepository = providerRepository;
        this.priceVersionRepository = priceVersionRepository;
    }

    public RouteDecision resolve(String alias, String requiredCapability) {
        LogicalModel logicalModel = logicalModelRepository.findByAliasAndEnabledTrue(alias)
                .orElseThrow(() -> new IllegalArgumentException("unknown logical model: " + alias));

        if (requiredCapability != null && !logicalModel.supports(requiredCapability)) {
            throw new IllegalArgumentException(
                    "logical model " + alias + " does not support capability: " + requiredCapability);
        }

        List<Deployment> candidates = deploymentRepository
                .findByLogicalModelIdAndEnabledTrueOrderByPriorityDesc(logicalModel.getId())
                .stream()
                .filter(d -> !"OPEN".equals(d.getHealthState()))
                .toList();

        if (candidates.isEmpty()) {
            throw new IllegalStateException("no available deployment for: " + alias);
        }

        int topPriority = candidates.get(0).getPriority();
        List<Deployment> samePriority = candidates.stream()
                .filter(d -> d.getPriority() == topPriority)
                .toList();

        Deployment chosen = pickByWeight(samePriority);

        Provider provider = providerCache.computeIfAbsent(chosen.getProviderId(),
                id -> providerRepository.findById(id)
                        .orElseThrow(() -> new IllegalStateException("provider not found: " + id)));

        PriceVersion priceVersion = priceVersionRepository.findById(chosen.getPriceVersionId())
                .orElseThrow(() -> new IllegalStateException(
                        "price version not found: " + chosen.getPriceVersionId()));

        return new RouteDecision(logicalModel, chosen, provider, priceVersion);
    }

    private Deployment pickByWeight(List<Deployment> deployments) {
        int total = deployments.stream().mapToInt(Deployment::getWeight).sum();
        if (total <= 0) {
            return deployments.get(ThreadLocalRandom.current().nextInt(deployments.size()));
        }
        int hit = ThreadLocalRandom.current().nextInt(total);
        int cursor = 0;
        for (Deployment d : deployments) {
            cursor += d.getWeight();
            if (hit < cursor) {
                return d;
            }
        }
        return deployments.get(deployments.size() - 1);
    }
}
```

再给一个只读的预览接口，把路由决策摊开，方便验证和排障。

```java
package com.example.gateway.web;

import com.example.gateway.routing.ModelRouter;
import com.example.gateway.routing.RouteDecision;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

import java.util.LinkedHashMap;
import java.util.Map;

@RestController
@RequestMapping("/admin/api")
public class RoutePreviewController {

    private final ModelRouter modelRouter;

    public RoutePreviewController(ModelRouter modelRouter) {
        this.modelRouter = modelRouter;
    }

    @GetMapping("/route-preview")
    public Map<String, Object> preview(@RequestParam String alias,
                                       @RequestParam(required = false) String capability) {
        RouteDecision decision = modelRouter.resolve(alias, capability);
        Map<String, Object> body = new LinkedHashMap<>();
        body.put("alias", decision.logicalModel().getAlias());
        body.put("modelType", decision.logicalModel().getModelType());
        body.put("capabilities", decision.logicalModel().getCapabilities().split(","));
        body.put("deployment", decision.deployment().getName());
        body.put("upstreamModel", decision.deployment().getUpstreamModel());
        body.put("providerCode", decision.provider().getCode());
        body.put("upstreamUrl", decision.upstreamUrl());
        body.put("priceVersion", decision.priceVersion().getVersion());
        return body;
    }
}
```

```sql
    weight INT NOT NULL DEFAULT 100,

    health_state VARCHAR(16) NOT NULL DEFAULT 'UNKNOWN',

);

    effective_from TIMESTAMP NOT NULL,
    CONSTRAINT uk_price_version_deployment_version UNIQUE (deployment_id, version)
```
