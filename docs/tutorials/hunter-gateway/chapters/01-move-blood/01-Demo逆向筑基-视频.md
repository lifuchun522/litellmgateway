先把 open-api.zip 逆透，再写第一行新代码。第一章叫上苍之手：看清 demo 有什么，再谈要什么。
客户不会为一份 As-Is 文档付钱。一句话说清：这套 Gateway 让谁少写多少代码，谁愿意为它买单。
接入方最怕文档和代码对不上。逆向必须给出接口清单和真实调用链，让第一次接入的人不用问第二遍。
我扫了六个同类开源 LLM 网关：先有可跑基线再谈抽象的，都在半年内持续迭代；先重构的普遍返工。
一期只做逆向和冻结：模块树、接口清单、调用链、ER、页面路由。重写、优化、加能力全部写进 Not Do。
两条路。A 全量重画架构再迁移，漂亮但工期三倍；B 逆向 demo 出复用矩阵，改名复用为主，两周可回归。
逆向最大的坑是只看代码不跑起来。我先原样编译启动，把接口和页面跑通，才敢判断哪块能复用。
没有基线就没法验收。我要三条线：一次编译启动成功、接口返回码一致、页面路由全可达，且可重复。
开发者是搜着来的。as-is.md 的标题要写清 Spring Boot、LLM 网关、逆向基线，用户搜什么我们写什么。
这次不投。转化事件还没埋，CAC 无法追踪，花钱只会买到假线索。基线冻结前，一分钱都不该花。
全量重构三人三个月，现金支出七位数。逆向冻结两周不到十分之一，安全边际高，这笔账我认。
先想最坏情况：demo 的许可能不能商用。逆向产物只放文档和复用矩阵，第三方源码不进主干。
逆向、跑通、文档、评审四条线，各写一个 Owner，每天交一个可见产物，否则就是人人参与、没人交付。
采纳 Alex，先跑通再定论。复用矩阵五类打标：直接、改名、重构、废弃、新增。牺牲架构美感，换两周可回归。
实现路径：原样编译启动，加拦截器打印真实调用链，再逐接口回归。幂等、超时、重试先不改，只记录现状。
范围现在冻结：一期只交 as-is.md、类图、时序图、风险清单、复用矩阵。后续能力全部延后，本章不碰业务代码。
补一个反证：同类项目跳过逆向直接重构的，半年内二次返工比例更高。但样本只有六个，置信度中高，仍需自证。
成功线：接口清单覆盖百分之百，一次启动成功，页面路由全可达。停止线：连续两天编译不过，降级为只交文档。
按客户路径复验：让没参与逆向的人只拿 as-is.md 去接一次接口。他能独立接通，这份基线才算真能用。
我改口。对外不讲架构多漂亮，只讲两天看清一套现有网关、拿到可复用清单。卖的是少走弯路，不是文档。
落地成结构：一章一页，标题写成问题句，正文挂接口清单和复用矩阵，内链回章节索引。验证看收录页数和自然点击。
明确不投。触发条件是复用矩阵被外部项目引用三次以上，那时再测一个渠道，预算上限五千，只买开发者关键词。
预算线：两人两周，不超过二十人日，不新增服务器。ROI 门槛是复用矩阵覆盖六成以上代码，否则本章算失败。
红线三条：不动第三方源码、不对外做商用承诺、逆向产物标注来源与日期。三条都满足，本章放行。
分工锁定：Bob 类图时序图，Alex 接口清单与调用链，Emma 复用矩阵，Iris 风险清单，T+10 合入本章分支。
拍板：不重造骨架，逆向 open-api demo，两周内冻结可回归基线。分支 chapter/01-reverse-demo，今天开工。
