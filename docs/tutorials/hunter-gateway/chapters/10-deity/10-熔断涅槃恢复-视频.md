第十章的交付物只有一个：Deployment 级健康熔断，故障自动摘除，恢复后自动重入路由。
客户不为熔断器付钱，只为不掉线付钱。摘除必须让用户少看到一次 502，否则别做。
上周工单里，单台 Deployment 拖垮整条路由，客户重试十一次没人接。这个必须闭环。
Resilience4j 的 CircuitBreaker 是成熟件，但 Deployment 级粒度少见，我先查同类网关怎么做。
一期只做四样：状态机、失败阈值、健康探测、操作页面。不做多集群联动和自动扩缩容。
方案 A 每 Deployment 一个熔断器加独立探针；方案 B 全局熔断加实例计数。A 隔离好，B 省内存。
探针成功会覆盖真实失败计数，这就把两个数据源揉成一个。半开时怎么判定谁能回池？
现在没有错误率基线，我拿不到摘除阈值。得先定义样本量、失败窗口和最小存活数。
文档页要把熔断状态写成可搜的词条：Deployment 摘除、半开探测、自动重入，别造新黑话。
这次不投钱。开源网关获客靠 GitHub 和文档，CAC 算不出来，先拿自然流量验证。
人力两周，服务器几乎不涨，最多多一个健康检查开销。预算线就是两周，超了砍页面。
手工 Disable 必须记操作人和时间，自动恢复不能覆盖人工决定。出事要能拿出这条链路证据。
顺序定了：状态机、探测分离、路由摘除、页面、验收。Bob 出契约，Alex 拿实现。
我接受砍掉多集群联动，但页面必须让人一眼看到哪台被摘了。这条不能省，其余都可以等。
按一线标准，我只认两件事：故障三十秒内摘除，恢复后重入不再报错。做不到就回炉。
同类网关多用实例级摘除加最小存活数保护，置信度中等。建议加存活下限，避免一次全摘。
范围冻结：四件套保留，加上最小存活数保护和操作审计。时间不变，页面砍掉两张图。
最终取方案 A：每 Deployment 一个熔断器，探针走独立通道，牺牲内存换隔离和可解释性。
真实请求进滑动窗口，探针只发健康信号。半开只放一个探针请求，超时或失败立刻回 OPEN。
基线：错误率百分之五、慢调用占比百分之二十触发 OPEN。成功线是故障自动摘除率达九成五。
我把熔断状态做成可索引文档，验证指标是这页的自然搜索进入量和 GitHub 跳转量。
CAC 无法归因，本轮零预算。若两周内这页带来五十个 star，下一章再谈付费验证。
预算锁定两周一个人力，页面从五张砍到三张。亏损上限就是这两周，超支立刻停。
加上操作人留痕和手工优先后，这条链路可以写进运维手册。红线：自动恢复不得覆盖人工 Disable。
Owner：Bob 出契约，Alex 写实现，Emma 验页面。分支 chapter/10，周五提测，下周三验收。
就做方案 A，两周交付。验收两条：故障三十秒自动摘除，恢复后自动重入。做不到就回退。
