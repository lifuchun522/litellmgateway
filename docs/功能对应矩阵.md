# LLM Gateway 功能对应矩阵

## 1. `open-api.zip` 到 LLM Gateway 的语义映射

| 参考工程概念 | LLM Gateway 概念 | 本次实现位置 | 对应说明 |
|---|---|---|---|
| `OpenApp` | 应用、凭证 | `gateway_application`、`gateway_credential` | 保留调用方身份与状态，增加数据分级、额度和预算 |
| `OpenApi` | 模型别名、提供商端点 | `gateway_alias`、`gateway_provider`、`gateway_endpoint` | 一个稳定别名可映射多个真实模型端点 |
| `OpenAppApi` | 应用+别名策略授权 | `gateway_policy`、`gateway_alias_endpoint` | 从静态授权扩展为可审批、可发布的路由策略 |
| `OpenCallLog` | 请求、尝试、审计 | `gateway_request`、`gateway_attempt`、`audit_logs` | 一次逻辑请求可关联多次端点尝试，并记录快照版本 |
| API 密钥校验 | 应用身份绑定 | `invoke()` 身份校验、M3-R001 | 调用前绑定活动应用；生产化时替换为哈希凭证验证 |
| 接口代理 | LLM 路由数据面 | `select_candidates()`、`invoke()` | 增加能力、数据等级、健康、优先级与首字节边界 |

## 2. 需求功能与交付物对应

状态定义：**已实现**为可通过界面/API 运行；**原型实现**为确定性模拟核心语义；**模型预留**为本体和界面信息架构已覆盖，后续需接入生产基础设施。

## 3. 推荐生产化顺序

1. 接入真实 OpenAI-compatible 上游适配器与流式转发。
2. 接入 KMS/Vault、凭证哈希验证、轮换和吊销。
3. 落地 Redis 限流、预算账本和可靠 Outbox/WAL。
4. 将快照分发扩展为多 AZ ACK，增加 30 秒滑窗熔断状态机。
5. 补齐控制面 CRUD、FinOps 和应急授权审批页面。
