一个单体进程收敛全部职责：后台管理 + 开放网关同进程

Section 01 · Context

一个 jar，两个对外身份

既是服务端渲染的后台管理平台（Thymeleaf 144 个模板），
也是面向第三方的 OpenAPI 网关（/open/** 统一转发）

两类使用者，两套凭据体系

浏览器用户走 Shiro 服务端会话（30 分钟超时）；第三方调用方走
X-App-Key + HmacSHA256 签名，不建立任何会话

网关不共用安全框架

/open/** 与 /selftest/** 在 ShiroConfig 中显式配置为
anon，由 OpenApiFilter 自行完成签名鉴权

存储只有 PostgreSQL 11 一个实例

34 张表：open_* 5 张 + sys_*/gen_* + QRTZ_* 11 张；
无视图、无存储过程、无物理外键

过滤链五段齐备，但防护段默认关闭 —— POST 请求无 CSRF 校验

Section 05 · Security

兜底链五段按序执行

/** → user, kickout, onlineSession, syncOnlineSession,
csrfValidateFilter；模板由 ShiroConfig 装配

防护段被开关关闭

csrf.enabled=false（配置与默认值都是 false），白名单
csrf.whites=/druid 同步失效；页面仍下发 Token 元数据

两段过滤器实际不生效

maxSession=-1 时 kickout 直接放行；sys-authCache 永久
缓存且 clearCachedAuthorizationInfo 全仓无调用点

另有两条专用链

/login 与 /register 追加 captchaValidate；/logout 走 logout；
XssFilter 注册在 Shiro 之前，仅覆盖 /system/* 与 /tool/* 两个前缀

一次网关调用拆成三段六组件：鉴权、转发、记录，缺一段即断

Section 06 · Gateway Chain

鉴权段：签名 + 时间戳 + 防重放

OpenApiFilter 先置 TraceContext，再由 OpenApiSecurityService
做 HmacSHA256 校验，时间漂移容忍 ±5 分钟

转发段：剥离签名头后转发

OpenGatewayController 接收 /open/**，OpenApiProxyService
用 RestTemplate 转发到 target_url，超时默认 5000ms

记录段：直插日志表，不在事务内

OpenApiLogService#save 用 JdbcTemplate.update 写
open_call_log，与鉴权查询同属裸 SQL 旁路

错误码两段式，网关侧自处理

鉴权 40001–40005、转发 50001–50002；网关异常在 Filter 内被
捕获，不进入 GlobalExceptionHandler 的 8 个处理器

防护件齐全但开关停在关闭位：设计强度不等于实际强度

Section 10 · Trade-off

设计侧：机制一件不缺

兜底链五段齐备、CsrfValidateFilter 已实现并挂在链上、
XssFilter 已注册、口令重试 5 次锁定 10 分钟

实际侧：四个开关停在反向

csrf.enabled=false、maxSession=-1、数据库与 Druid
监控台口令 123456、sys-authCache 永久缓存且无失效调用

缺口侧：权限码没有闭环

184 个端点中 79 个无 @RequiresPermissions；open:* 共 16 个
权限码只存在于菜单数据，后端零强制
