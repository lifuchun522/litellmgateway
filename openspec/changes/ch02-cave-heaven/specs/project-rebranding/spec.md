# Spec Delta

## Purpose

让一份「能跑但名字不是自己的」Java 工程，在不改变任何可观察行为的前提下换成自己的标识，并把「行为没变」变成可机械判定的证据，而不是一句「我检查过了」。

这个能力在 `open-api/qvsu-openapi`（Spring Boot 2.7.18）上首次落地，但本身与具体工程无关：换任何一份工程、换任何一套新旧标识，同一套纪律都必须成立。

## ADDED Requirements

### Requirement: 三级粒度的替换纪律

标识替换 SHALL 按三级粒度推进：一级为完整包名等可全仓批量、语义无歧义的替换；二级为 Maven 坐标、启动类名、配置前缀、任务类名等需要逐文件确认的替换；三级为品牌文案、镜像名、容器名、脚本注释等需要人工过清单的替换。

替换 MUST 由清单驱动，MUST NOT 由「改一处跑一次」的报错驱动。

#### Scenario: 一级替换可批量

- **WHEN** 执行一级替换（完整包名）
- **THEN** 替换对象是唯一的、不含歧义的完整标识符
- **AND** 替换后项目仍可通过编译

#### Scenario: 二级替换逐项确认

- **WHEN** 处理 Maven 坐标、启动类名、配置前缀、任务类名
- **THEN** 每一项在提交前都有对应的运行期验证证据（编译输出、启动日志或接口响应）
- **AND** 每一项都在本变更的 `design.md` 里列出

#### Scenario: 三级替换过清单

- **WHEN** 处理品牌文案、镜像名、容器名、脚本注释
- **THEN** 存在一份清单，逐条标明「已替换」或「有意保留 + 原因」
- **AND** 保留项被写进技术债清单并给出删除时间

### Requirement: 不改变行为

换骨 MUST NOT 改变任何可观察行为。方法体逻辑、接口路径、响应结构、状态码、鉴权算法 MUST NOT 发生变化。允许改变的只有标识符、配置键名、类名、文件名、资源名与注释文字。

#### Scenario: 接口行为逐项一致

- **WHEN** 在换骨前采集基线快照，换骨后采集当前快照，逐项比对
- **THEN** 每一项都完全一致，差异数为零
- **AND** 比对结果以退出码形式暴露（一致为 0，存在差异为非零）

#### Scenario: 允许的改动类型是可枚举的

- **WHEN** 审查换骨后的 diff
- **THEN** 除新增文件外，改动只落在 `package`/`import` 语句、类名与标识符、配置键名与注释、资源名、镜像与容器标识上
- **AND** 不包含任何控制流、表达式或方法签名的改动

#### Scenario: 差异出现即回退

- **WHEN** 回归比对发现任何一项行为差异
- **THEN** 停止推进并回退到基线分支
- **AND** MUST NOT 在回归现场直接改代码「让它过」

### Requirement: 旧配置前缀的兼容期

配置前缀迁移 SHALL 提供兼容期。新前缀存在时旧前缀 MUST 被整段忽略；只有旧前缀存在时，旧前缀的值 MUST 被搬到有效配置，并在日志与诊断接口中给出含生效键名的废弃警告；两者都不存在时 MUST NOT 产生任何副作用。兼容期 MUST 有明确终点。

#### Scenario: 只有旧前缀

- **WHEN** 配置中只有旧前缀的键
- **THEN** 应用照常启动
- **AND** 配置类读到旧前缀的值
- **AND** 兼容状态标记为已生效，并记录生效的键名

#### Scenario: 新旧前缀同时存在

- **WHEN** 配置中同时存在新旧前缀
- **THEN** 新前缀生效
- **AND** 旧前缀的值一个都不被采用
- **AND** 记录「旧前缀可以删除」的提示

#### Scenario: 旧前缀的未知键

- **WHEN** 旧前缀下出现配置类不认识的键
- **THEN** 该键被忽略，不抛异常，不影响其它键的搬运

#### Scenario: 兼容状态可观测

- **WHEN** 请求兼容诊断接口
- **THEN** 返回内容包含是否走兼容分支、生效键名、新前缀是否存在、旧前缀是否存在、以及当前有效的应用名与版本
- **AND** 该接口只读，且返回内容中不含任何密钥

#### Scenario: 兼容状态可复位

- **WHEN** 在同一进程内连续做两次判定
- **THEN** 第二次判定不受第一次影响
- **AND** 存在显式的复位入口供测试使用

### Requirement: 残留扫描门禁

仓库 SHALL 提供一个可重跑的残留扫描：命中旧包名、旧配置前缀或旧制品/镜像标识即失败。扫描 MUST 明确列出有意保留的旧标识及其原因。

#### Scenario: 无残留即通过

- **WHEN** 执行残留扫描且仓库内所有旧标识都已替换
- **THEN** 扫描以 0 退出
- **AND** 输出中明确说明哪些旧串属有意保留

#### Scenario: 有残留即失败

- **WHEN** 在源码或配置里重新引入任一旧标识
- **THEN** 扫描以非零退出
- **AND** 逐条打印命中位置（文件:行号:内容）

#### Scenario: 两套实现等价

- **WHEN** 分别在 Linux 与 Windows 上执行两侧扫描脚本
- **THEN** 两者对同一仓库给出相同的结论（通过/失败）

### Requirement: 字符串形式的引用必须单独扫

换骨 MUST 覆盖编译器不检查的字符串引用，至少包括：ORM 映射文件的命名空间、日志组件的 logger 名、启动横幅的属性占位符、框架放行路径、数据库里存储的「Bean 名.方法名」调用目标。

#### Scenario: ORM 命名空间

- **WHEN** 应用启动并访问任一依赖 ORM 映射的页面
- **THEN** 不出现「绑定语句未找到」类错误

#### Scenario: 日志组件名

- **WHEN** 应用启动
- **THEN** 应用自身包名的日志按配置的级别输出（debug 级别可见）

#### Scenario: 启动横幅占位符

- **WHEN** 应用启动
- **THEN** 横幅上的版本号解析为配置里的真实值，而不是原样打印占位符

#### Scenario: 数据库中的调用目标

- **WHEN** 定时任务表中的调用目标仍指向旧方法名
- **THEN** 提供一段幂等的数据库升级语句，把方法名改为新值
- **AND** Bean 名在兼容期内保持不变，以免已存在的任务找不到目标

### Requirement: 产物与容器标识同步

构建产物名、镜像名、容器名、编排文件里的服务名 SHALL 与新的项目口径一致，MUST NOT 残留旧标识。

#### Scenario: 产物名

- **WHEN** 执行打包
- **THEN** 产物文件名与新的项目标识一致

#### Scenario: 容器化资产

- **WHEN** 检索部署目录
- **THEN** 不再出现旧的镜像名、容器名或旧产物名

### Requirement: 回归尺子随仓库版本化

黄金基线快照与回归脚本 SHALL 随仓库版本化，MUST NOT 只存在于某台开发机的临时目录里。回归脚本 MUST 能在两侧平台运行，且 MUST 排除「输入样例」这类非行为文件。

#### Scenario: 基线快照入库

- **WHEN** 查看仓库
- **THEN** 能找到基线快照目录与回归脚本
- **AND** 能在换骨前后各跑一次并得到可比较的结果

#### Scenario: 输入样例不被当作行为快照

- **WHEN** 执行回归比对
- **THEN** 请求样例文件被排除在比对之外
- **AND** 输出中不出现「基线有样例文件、当前缺失」这类假差异

#### Scenario: 差异可定位

- **WHEN** 某一项行为发生变化
- **THEN** 输出逐项标明「一致」或「差异」，并对差异项给出基线与当前的具体内容
